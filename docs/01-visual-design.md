# 随行（dipi）· 小程序端视觉设计规范

> 文档版本：v1.0 · Phase 1 视觉方向 · 负责人：米拉（视觉设计架构师）
> 主题：**浅色（light）固定**，不提供深色皮肤。
> 基准屏宽：**375px**（= 750rpx，rpx 换算：1px = 2rpx）。
> 关联产出：`miniprogram/styles/tokens.wxss`（设计令牌）、`miniprogram/styles/components.wxss`（组件视觉类）。
> 本文档只定义**视觉层**。信息架构与交互流程由 UX 阶段（优希）输出，本文档不越界。

## 1. 美学定位

### 1.1 品牌气质（一句话）

> **「在地的手艺人带你逛」——把地陪当作一位有温度、有分寸的专业向导，而不是一个货架上的商品。**

关键词：**可信、克制、有人味、当地感**。

展开说：「随行」卖的不是信息，是**信任与陪伴**。所以视觉目标是**暖底色 + 冷静的结构**：用松绿作为主色（代表可靠、专业、被信任），用陶土红只出现在价格与评分（代表热度、人情味、烟火气），整体保持低饱和度，避免旅游行业常见的花哨。

**一句话否决器（用于评审时快速判断）**：如果一个设计看起来像「优惠券大促页」或「旅游攻略内容社区」，就是错的方向。

### 1.2 目标人群画像

| 维度 | 描述 | 视觉含义 |
|---|---|---|
| 主画像 A：**异乡自由行者** | 25–35 岁，一二线城市白领，独自或与 1–2 位同伴出行；用小红书/马蜂窝做行程灵感，但决策卡在「不敢自己找本地人」。 | 需要「安全感」：清晰的价格、可验证的评分、真实头像、正面照片位。信息密度**中高**，价格必须一眼可见。 |
| 主画像 B：**异地商务/探亲访客** | 30–50 岁，出差或探亲，时间紧、目标明确（1–2 天、机场接送、代排队办事）。 | 需要「效率」：服务类型一眼分清、可选项少而明确、时间与路线信息结构化。**少装饰、强信息层级**。 |
| 次画像 C：**亲子家庭陪同者** | 30–45 岁家长，预订亲子陪玩/城市漫游，希望安全、正向、轻松。 | 需要「温度」：柔和配色、圆润但不过度的圆角、亲和的头像比例；避免硬冷色块。 |
| 次画像 D：**地陪本人（供给侧）** | 20–40 岁本地人/兼职向导，用手机接单与沟通，移动端长时间使用。 | 需要「低疲劳」：聊天页高对比大字、按钮触达区 ≥ 44px、弱化装饰。 |

**设计优先服务 A 与 B**（占交易量主体），C 用色彩与圆角的柔性调节满足，D 通过组件规范的无障碍基线兜底。

### 1.3 竞品调性差异

| 维度 | 马蜂窝 | 小红书 | 抖音本地生活 | **随行（我们）** |
|---|---|---|---|---|
| 核心 | 内容攻略 | UGC 种草 | 内容 + 团购 | **服务履约与预约** |
| 视觉主调 | 高饱和蓝绿、大图瀑布流、圆角 12px+、信息密 | 大红 + 白、内容卡片、大圆角（12–16px）、强 emoji | 黑底霓虹、动效强 | **低饱和松绿 + 陶土红，浅底 + 白卡，中密度** |
| 视觉母题 | 攻略文章 | 种草笔记 | 团购券 | **向导名片 + 服务清单** |
| 价格呈现 | 混杂 | 隐藏/引导私聊 | 券后价标签 | **价格是核心信息，等级/单位明确，右下固定位** |
| 情感 | 攻略感 | 分享欲 | 便宜/冲动 | **被陪同的安心感 + 当地烟火气** |

**刻意不同的三处（可直接用于评审对照）：**

1. **不做内容瀑布流。** 首页以「横向滑动的地陪卡片 + 目的地选择」为主结构，而不是无限下拉大图。理由：随行的转化对象是**人**，不是图文；内容密度让位给**人物可信度**。
2. **不用内容社区的高饱和撞色。** 主色选松绿（`#0F6F63`）而非旅行行业默认蓝/青绿撞色；彩度上限锁死在 **≤ 34%（文字类）/ ≤ 76%（实心块）**，用**面积小 + 高对比**制造记忆点，而不是大面积铺色。
3. **价格前置且视觉唯一。** 全 App 里**只有价格和评分用陶土红**，且**一个视口内最多出现一处红色实心块**。这让「用户扫到价格」变成肌肉记忆，也天然避开优惠券页观感。

### 1.4 视觉隐喻与禁则

- **隐喻**：行程单 / 门票存根（细横线、等宽数字、印章式角标），暗示「线下、真实、可凭票履约」。
- **禁则**：不要把「随行」做成旅行社 App —— 禁止出现飞机✈️ 大图标贴纸、禁止把行程做成带飞机头的路线图、禁止大面积机票蓝。

## 2. 设计原则（4 条 · 每条可执行 · 可被违反性检查）

### 原则 1｜**一个视口最多一个视觉主角**

**定义**：任一屏内，允许存在 **≤ 1 处**「主行动按钮（主色实心）」+ **≤ 1 处**「强调色实心块（陶土红）」。两者同屏时，红色块必须是价格，且必须与主按钮不在同一视觉组内。

**可执行规则**：
- 主色实心填充元素每屏 ≤ 1 个；若列表项内含按钮，列表项内的按钮一律用**次级（描边/浅底）**样式。
- 陶土红实心元素每屏 ≤ 1 个，且仅限价格数字或已选中的筛选项；评分星形用 `accent-500` 线稿填充，属图标类，不计入。

**违反性检查（任何一条命中 = 违规）**：
- 首页同时出现「立即预约」主按钮 × N 个地陪卡（全卡片都是主按钮）。
- 搜索页筛选条出现红色实心 chip × 3。
- 订单详情页同时有红色价格块和红色状态徽章。

---

### 原则 2｜**信息密度靠留白与分隔线，不靠字号与颜色**

**定义**：一屏内**字号档位 ≤ 3 档**；层级差异用 **字重（400 / 500 / 600）+ 色阶（ink-900 / ink-700 / ink-500）** 表达。行高留白按标尺执行，不允许为了塞内容压行高。

**可执行规则**：
- 单个文本块的字号必须来自字号阶梯（`display/title/body/caption/label`），**不允许出现阶梯外的数值**（如 27rpx、32rpx 正文）。
- 正文行高固定 `44rpx`（22px），不得压到 `1.3` 以下；卡片正文行高 `40rpx`。
- 同屏出现 `caption` 与 `label` 两档小字时，`label` 仅用于徽章/角标，不用于句子。

**违反性检查**：
- 地陪卡片里出现 24rpx、26rpx、28rpx 三种正文尺寸。
- 聊天页消息正文与时间戳使用同一字号（时间戳必须 `caption` 且用 `ink-500`）。

---

### 原则 3｜**暖色只给"人"和"价格"，冷色给"系统"**

**定义**：松绿（品牌）与陶土红（强调）承担**人的温度**；中性灰阶承担**系统结构**；功能色（绿/黄/红/蓝）**仅**用于状态语义，**不得**用于装饰。

**可执行规则**：
- 陶土红 `accent-*` 只允许出现在：**价格数字、评分星级、已选中筛选 chip、订单徽章中的「行动级」状态（待确认 / 退款中）**。四者之外的任何位置不得使用。
  - 「行动级橙徽章」是**唯一**允许 accent 出现在状态徽章上的情形，且只用 `accent-100` 浅底 + `accent-700` 字（**禁止** `accent-600` 实心底）。
  - **同一张订单卡内**，若已有行动级橙徽章，价格必须降级为 `ink-900`（见 §6.10「一卡两橙的处理」）。
- 功能色 `success/warning/error/info` 只允许出现在：**状态徽章、表单校验提示、Toast**。页面主按钮永远用 `brand-*`，错误态按钮永远用 `error-*`。
  - 订单徽章中 `error-*` **只**用于「纠纷 / 异常」；「退款中」用 accent 橙，「已退款」用中性灰（见 §6.10）。
- 页面底色恒为 `ink-100`，卡片恒为 `surface`（白），**不用彩色卡片底**（唯一例外：`brand-50` / `accent-50` 浅底用于「被选中态」与「提示条」，且面积 ≤ 屏 8%）。

**违反性检查**：
- 用 `info-600` 蓝色做「立即预约」按钮。
- 用 `success-600` 绿色当主按钮色（会让用户以为是「已完成」）。
- 空状态插画用渐变紫粉。

---

### 原则 4｜**375px 上不拥挤：触控 ≥ 88rpx，文字 ≥ 24rpx，可点区 ≥ 88×88rpx**

**定义**：所有**可点击元素**最小触达尺寸 `88rpx × 88rpx`（44×44px）；所有**真实阅读的文字**最小 `24rpx`（12px）；价格与评分是全 App 唯一允许「放大」的强调元素。

**可执行规则**：
- 任何 `view` 上绑 `bindtap` 时，其渲染盒子必须 ≥ 88rpx 高；若视觉元素更小（如 16rpx 的叉号），必须用 `padding` 或外层容器补足到 88rpx。
- 最小字号 `24rpx`（caption）仅用于辅助说明与时间戳，**不得**用于价格、服务名、按钮文案。
- 375px 宽度下，**单行不截断**的内容：地陪名 ≤ 8 字、服务标签 ≤ 4 个（超过用 `+N`）。

**违反性检查**：
- 聊天输入框发送按钮是 32rpx 的图标。
- 标签 chip 高度 40rpx（可点但触达不足 44px 逻辑高，需 `padding` 补足）。
- 标签栏/筛选项文字用 20rpx。

## 3. 色彩系统

### 3.1 使用规则（先读这里）

1. **页面底** = `--dipi-ink-100` (`#F2F4F3`)，**卡片** = `--dipi-surface` (`#FFFFFF`)。二者对比度仅 1.06:1，靠 **1px 分割线 + 4rpx 阴影**区分，不要靠加深页面底色。
2. **文字只有四档**：ink-900（正文/标题）、ink-700（次要）、ink-500（辅助/时间戳）、ink-400（禁用/占位）。
3. **品牌色有 3 种用法**：实心按钮底（brand-600）、文字/图标（brand-700 或 brand-600）、浅底（brand-50/brand-100）。
4. **红色只给价格**（见原则 3）。

### 3.6 颜色分配比例（守则）

- **中性灰（ink-*）+ 白** = 约 **88%** 面积
- **品牌松绿** = 约 **8%** 面积
- **陶土红** = **≤ 3%** 面积
- **功能色** = **≤ 1%** 面积

## 4. 字体排印

### 4.1 字体栈

```css
/* 中文正文 / 全局 */
--dipi-font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Helvetica Neue",
                   "Hiragino Sans GB", "Microsoft YaHei", "Source Han Sans SC", sans-serif;

/* 数字（价格、评分、时间戳）——等宽数字，避免跳动 */
--dipi-font-num: "SF Pro Display", "Helvetica Neue", "DIN Alternate", "Roboto", var(--dipi-font-sans);
```

## 5. 栅格与间距

### 5.1 栅格

- 基准屏宽 **375px** = **750rpx**。所有尺寸用 `rpx`，仅 `border: 1px` 用 `px`（真机更清晰），阴影模糊半径用 `rpx`。

### 6.5 地陪卡片 `.dipi-guide-card`

**结构（横向）**：头像 `120rpx` 圆形 → `24rpx` 间距 → 中间信息列（弹性） → `16rpx` 间距 → 右侧价格列（固定 `160rpx`，右对齐）。

| 元素 | 规格 |
|---|---|
| 卡片 | 白底，`--dipi-radius-lg` (24rpx)，内边距 `24rpx`，`--dipi-shadow-xs`，外间距 `0 24rpx 24rpx` |
| 头像 | `120×120rpx`，圆角 `full`，描边 `2rpx` `--dipi-ink-100`；无头像时底色 `--dipi-ink-100`，内嵌「地」字 `--dipi-ink-400` `--dipi-fs-title` |
| 姓名 | `--dipi-fs-title` / 600 / `--dipi-ink-900`，单行省略，最多 8 字 |
| 头衔/认证 | `--dipi-fs-caption` / `--dipi-ink-500`，单行省略 |
| 评分 | 星级见 6.6 + 数字 `--dipi-fs-caption` / `--dipi-ink-700` |
| 服务标签 | `--dipi-fs-label` / 500 / `--dipi-brand-700`，底 `--dipi-brand-50`，圆角 `--dipi-radius-xs`，内边距 `4rpx 16rpx`，**最多 2 个 + `+N`**（见下方密度约束） |
| 城市/位置 | `--dipi-fs-caption` / `--dipi-ink-500`，前置 20rpx 定位图标 |
| 价格 | 右下角，见 6.4；列表页用 `--dipi-fs-price` (30rpx) |
| 「立即预约」 | **不在卡片内放实心主按钮**（原则 1）；卡片整体可点，按下 → `--dipi-shadow-sm` + `transform: scale(.99)` |

**四态**：
- 默认：上表。
- 按下：`--dipi-shadow-sm`，背景仍为白，卡片整体 `opacity .96`。
- 禁用（下架/休息中）：整卡 `opacity .45`，头像右上角加 `--dipi-ink-50` 底的「休息中」label（`--dipi-ink-500` 文字），价格不显示。
- 错误（加载失败）：占位块高 `180rpx`，底 `--dipi-ink-50`，文案「加载失败，点击重试」`--dipi-fs-caption` `--dipi-ink-500`，右下角「重试」文字按钮 `--dipi-brand-600`。

**⚠️ 服务标签密度约束（实测 375px 得出，易被忽略）**

375px 屏下，中间信息列实际可用宽约 **300rpx（150px）**（= 702rpx 内容宽 − 120rpx 头像 − 24rpx 头像间距 − 160rpx 价格列 − 16rpx 间距 − 24rpx×2 卡片内边距）。经 2 倍渲染实测：

- 3 个四字标签（如「老城美食」「会讲方言」「拍照跟拍」）会**换行成两行**，导致相邻卡片高度不一致（实测卡片 1 比卡片 2 高约 40rpx），列表视觉节奏被打乱。
- 因此规范为：**最多显示 2 个标签 + 1 个 `+N` 角标**（`+N` 用 `--dipi-ink-100` 底 / `--dipi-ink-500` 文字）。
- 容器必须 `flex-wrap: nowrap` + `overflow: hidden`（已写入 `components.wxss`），标签 `flex-shrink: 0`，确保**永不换行**、标签行恒为单行 `36rpx` 高。
- 标签左右内边距用 `--dipi-space-2`（8rpx）而非 `--dipi-space-3`，为 2 标签 + `+N` 留出安全余量。
- **数据层要求**：后端返回的标签数组超过 2 个时，前端必须折叠为「前 2 个 + `+N`」，不要靠 CSS 裁切硬切。

### 6.10 订单状态徽章 `.dipi-badge`

**尺寸**：高 `40rpx`，圆角 `--dipi-radius-xs` (8rpx)，内边距 `0 16rpx`，文字 `--dipi-fs-label` (22rpx) / 500。

**设计逻辑：按「视觉紧迫度」分 6 级，而非按业务状态逐个配色。** 依据是**用户需不需要立刻做动作**：需要 → 暖色（召唤）；在推进 → 品牌绿；妥了 → 绿；结束了 → 中性灰。只有真正的异常才用红。

| 紧迫度 | 覆盖状态 | 徽章文案 | 类 | 底/字 token | 实测对比度 |
|---|---|---|---|---|---|
| ① 还没确认，有时限 | 待支付 | 待支付 | `pending` | warning-100 / warning-700 | 6.02:1 ✅ |
| ① 还没确认，有时限 | 待接单 | 待接单 | `pending` | warning-100 / warning-700 | 6.02:1 ✅ |
| ② 已确认，等开始 | 已接单 | 已接单 | `ongoing` | brand-100 / brand-700 | 6.58:1 ✅ |
| ③ 正在进行 | 服务中 | 服务中 | `ongoing` | brand-100 / brand-700 | 6.58:1 ✅ |
| ④ **等你行动 / 关注** | 待确认 | 待确认 | `review` | accent-100 / accent-700 | 6.04:1 ✅ |
| ④ **等你行动 / 关注** | 退款中 | 退款中 | `refunding` | accent-100 / accent-700 | 6.04:1 ✅ |
| ⑤ 顺利完成 | 已完成 | 已完成 | `done` | success-100 / success-700 | 5.82:1 ✅ |
| ⑥ 已结束 | 已取消 | 已取消 | `closed` | ink-100 / ink-500 | 4.54:1 ✅ |
| ⑥ 已结束 | 已关闭 | 已关闭 | `closed` | ink-100 / ink-500 | 4.54:1 ✅ |
| ⑥ 已结束 | **已退款** | 已退款 | `closed` | ink-100 / ink-500 | 4.54:1 ✅ |
| ⚠️ 异常 | 纠纷 / 异常 | 纠纷 | `dispute` | error-100 / error-700 | 5.74:1 ✅ |

**类名 = 视觉层级，不是业务状态名。** 同一层级可承载多个业务状态（如 `pending` 同时对应「待支付」「待接单」），靠**徽章文案**区分，不靠颜色区分。

**`confirmed` 的保留用途（勿误用）**

`.dipi-badge--confirmed`（info 蓝，info-100 / info-700，**6.97:1**）在新的 6 级体系中**不再用于任何订单状态**（已接单/服务中统一走 `ongoing` 品牌绿）。它保留给**非订单类信息徽章**：`系统通知`、`处理中`、`平台介入中` 等。

> ⚠️ **「已接单」不要用 `confirmed`（蓝），要用 `ongoing`（绿）。** 蓝＝系统在处理，与订单的业务阶段不同，混用会破坏 6 级色板的语义一致性。

**两条语义决策（已按此落地，勿回退）**

1. **「已退款」用中性灰，不用红。** 它是**已完成的好结果**（钱退回来了），用 error 红会让用户误以为出了问题。
2. **红色专供「纠纷 / 异常」。** 退款中移到橙之后，error 红在整个 App 里只剩真正的异常，色板纪律更清晰。

**`--refund` 与 `--refunding` 的命名陷阱（重要）**

两个类名极像但**颜色与语义相反**：

| 类名 | 语义 | 颜色 |
|---|---|---|
| `.dipi-badge--refunding` | **退款中**（进行中，需关注） | 橙 accent |
| `.dipi-badge--dispute` | **纠纷 / 异常** | 红 error |
| `.dipi-badge--refund` | **已废弃**，是 `dispute` 的兼容别名 | 红 error |

> ⚠️ **新代码一律用 `dispute`，不要用 `refund`。** `refund` 仅保留以兼容既有前端白名单，视觉与 `dispute` 完全相同（error-100 / error-700），**不构成回归**。

**实心徽章**（仅「待支付」在订单页顶部强调条使用）：底 `--dipi-warning-600`，字白 **5.42:1**。
- 徽章**不得**使用渐变、不加阴影、不加圆角胶囊以外形状。
- 徽章紧贴订单标题**左上角**，不放在右侧（右侧留给价格/操作）。
- 徽章**不得**使用 `--dipi-accent-600` 实心底（那是价格专用），行动级徽章只用 `accent-100` 浅底 + `accent-700` 字。

**⚠️ 一卡两橙的处理（易被忽略）**

订单卡片同时含「行动级橙徽章」（待确认 / 退款中）与「橙色价格」时，一屏内出现两处暖色，违反**原则 1（一个视口最多一个视觉主角）**。

**规范**：订单卡带有行动级橙徽章时，价格降级为正文色。

```html
<!-- 有待确认/退款中徽章 → 价格降级为 ink-900 -->
<view class="dipi-order-card dipi-order-card--has-action-badge"> … </view>
<!-- 无行动级徽章 → 价格保持 accent-600 -->
<view class="dipi-order-card"> … </view>
```

实测：`accent-100` 底徽章与 `accent-600` 价格属**不同视觉通道**（浅底块 vs 纯文字），可共存于同屏；真正要防的是**同一张卡片内**两处暖色相撞。降级后一卡最多一处暖色。

## 7. 「避免清单」（降低返工的硬性禁令）

> 以下每条都**不可协商**，评审时可直接引用编号。

| # | 禁止 | 原因 / 替代 |
